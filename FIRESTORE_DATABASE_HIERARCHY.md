# Firestore Database Hierarchy

This document describes the complete structure of the Firestore database for the Straights Psyroll application.

## Database Structure Overview

```
straights_psyroll (Firestore Database)
│
└── users (Collection)
    └── {userId} (Document)
        ├── uid: String
        ├── email: String
        ├── name: String
        ├── phone: String
        ├── designation: String
        ├── profileImageUrl: String
        ├── isProfileComplete: Boolean
        │
        ├── attendance (Subcollection)
        │   └── {attendanceId} (Document)
        │       ├── id: String
        │       ├── checkInTime: Timestamp
        │       ├── checkOutTime: Timestamp (nullable)
        │       ├── checkInLocation: String
        │       ├── checkOutLocation: String (nullable)
        │       ├── checkInLatitude: Double (nullable)
        │       ├── checkInLongitude: Double (nullable)
        │       ├── checkOutLatitude: Double (nullable)
        │       └── checkOutLongitude: Double (nullable)
        │
        └── documents (Subcollection)
            └── {documentId} (Document)
                ├── id: String
                ├── fileName: String
                ├── fileUrl: String
                ├── uploadedAt: Timestamp
                ├── fileType: String
                └── fileSize: Int
```

### Key Architecture Points:
- ✅ **Each user owns their data** - All attendance and documents are nested under the user
- ✅ **Easy data isolation** - Deleting a user automatically enables deletion of all subcollections
- ✅ **Natural hierarchy** - Data structure mirrors real-world relationships
- ✅ **Better security** - Subcollections inherit parent document security context

## Detailed Collection Descriptions

### 1. **users** Collection

**Purpose**: Stores user profile information for all registered users in the application.

**Document Structure**:
- **Document ID**: Firebase Auth User UID (auto-generated by Firebase Authentication)
- **Fields**:

| Field Name | Data Type | Required | Description | Example |
|------------|-----------|----------|-------------|---------|
| `uid` | String | Yes | Unique user identifier (matches document ID) | `"abc123xyz789"` |
| `email` | String | Yes | User's email address | `"john.doe@example.com"` |
| `name` | String | Yes | User's full name | `"John Doe"` |
| `phone` | String | Yes | User's phone number | `"+1234567890"` |
| `designation` | String | Yes | User's job title or role | `"Senior Developer"` |
| `profileImageUrl` | String | No | URL to user's profile image in Firebase Storage | `"https://storage.googleapis.com/..."` |
| `isProfileComplete` | Boolean | Yes | Flag indicating if user has completed profile setup | `true` or `false` |

**Indexes**:
- Single field index on `email` (for user lookup)
- Single field index on `isProfileComplete` (for filtering incomplete profiles)

**Security Rules**:
```javascript
// Users can read and write their own document
match /users/{userId} {
  allow read: if request.auth != null && request.auth.uid == userId;
  allow write: if request.auth != null && request.auth.uid == userId;
}
```

### 2. **attendance** Subcollection (under users/{userId})

**Purpose**: Stores all check-in and check-out records for a specific user's attendance tracking.

**Path**: `users/{userId}/attendance/{attendanceId}`

**Document Structure**:
- **Document ID**: Auto-generated by Firestore
- **Parent Reference**: Implicitly linked to user via subcollection path
- **Fields**:

| Field Name | Data Type | Required | Description | Example |
|------------|-----------|----------|-------------|---------|
| `id` | String | Yes | Unique attendance record identifier (matches document ID) | `"att_abc123xyz789"` |
| `checkInTime` | Timestamp | Yes | Date and time of check-in | `Timestamp(2025-11-03 09:00:00)` |
| `checkOutTime` | Timestamp | No | Date and time of check-out (null if not checked out yet) | `Timestamp(2025-11-03 18:00:00)` or `null` |
| `checkInLocation` | String | Yes | Address/location where user checked in | `"123 Main St, City"` |
| `checkOutLocation` | String | No | Address/location where user checked out (null if not checked out) | `"123 Main St, City"` or `null` |
| `checkInLatitude` | Double | No | GPS latitude coordinate for check-in location | `37.7749` |
| `checkInLongitude` | Double | No | GPS longitude coordinate for check-in location | `-122.4194` |
| `checkOutLatitude` | Double | No | GPS latitude coordinate for check-out location | `37.7749` |
| `checkOutLongitude` | Double | No | GPS longitude coordinate for check-out location | `-122.4194` |

**Note**: `userId` field is NOT needed because the user relationship is defined by the subcollection path.

**Computed Fields** (calculated in app, not stored in Firestore):
- `workingHours`: Duration calculated from `checkInTime` and `checkOutTime`

**Indexes**:
- Single field index on `checkInTime` (Descending) - for fetching user's attendance history ordered by date

**Security Rules**:
```javascript
// Users can only access their own attendance subcollection
match /users/{userId}/attendance/{attendanceId} {
  allow read: if request.auth != null && request.auth.uid == userId;
  allow create: if request.auth != null && request.auth.uid == userId;
  allow update: if request.auth != null && request.auth.uid == userId;
  allow delete: if request.auth != null && request.auth.uid == userId;
}
```

**Query Patterns**:
1. Get today's attendance (most recent):
   ```dart
   FirebaseFirestore.instance
     .collection('users')
     .doc(userId)
     .collection('attendance')
     .where('checkInTime', isGreaterThanOrEqualTo: startOfDay)
     .where('checkInTime', isLessThanOrEqualTo: endOfDay)
     .orderBy('checkInTime', descending: true)
     .limit(1)
   ```

2. Get all attendance for today:
   ```dart
   FirebaseFirestore.instance
     .collection('users')
     .doc(userId)
     .collection('attendance')
     .where('checkInTime', isGreaterThanOrEqualTo: startOfDay)
     .where('checkInTime', isLessThanOrEqualTo: endOfDay)
     .orderBy('checkInTime', descending: true)
   ```

3. Get weekly stats (last 7 days):
   ```dart
   FirebaseFirestore.instance
     .collection('users')
     .doc(userId)
     .collection('attendance')
     .where('checkInTime', isGreaterThanOrEqualTo: sevenDaysAgo)
     .orderBy('checkInTime', descending: true)
   ```

4. Get attendance history (paginated):
   ```dart
   FirebaseFirestore.instance
     .collection('users')
     .doc(userId)
     .collection('attendance')
     .orderBy('checkInTime', descending: true)
     .limit(20)
   ```

### 3. **documents** Subcollection (under users/{userId})

**Purpose**: Stores metadata for documents uploaded by a specific user (actual files stored in Firebase Storage).

**Path**: `users/{userId}/documents/{documentId}`

**Document Structure**:
- **Document ID**: Auto-generated by Firestore
- **Parent Reference**: Implicitly linked to user via subcollection path
- **Fields**:

| Field Name | Data Type | Required | Description | Example |
|------------|-----------|----------|-------------|---------|
| `id` | String | Yes | Unique document identifier (matches document ID) | `"doc_abc123xyz789"` |
| `fileName` | String | Yes | Original name of the uploaded file | `"passport.pdf"` |
| `fileUrl` | String | Yes | URL to the file in Firebase Storage | `"https://storage.googleapis.com/..."` |
| `uploadedAt` | Timestamp | Yes | Date and time when document was uploaded | `Timestamp(2025-11-03 10:30:00)` |
| `fileType` | String | Yes | MIME type of the file | `"application/pdf"`, `"image/jpeg"` |
| `fileSize` | Int | Yes | File size in bytes | `1048576` (1 MB) |

**Note**: `userId` field is NOT needed because the user relationship is defined by the subcollection path.

**Indexes**:
- Single field index on `uploadedAt` (Descending) - for fetching user's documents ordered by date

**Security Rules**:
```javascript
// Users can only access their own documents subcollection
match /users/{userId}/documents/{documentId} {
  allow read: if request.auth != null && request.auth.uid == userId;
  allow create: if request.auth != null && request.auth.uid == userId;
  allow delete: if request.auth != null && request.auth.uid == userId;
}
```

**Query Patterns**:
1. Get all user documents:
   ```dart
   FirebaseFirestore.instance
     .collection('users')
     .doc(userId)
     .collection('documents')
     .orderBy('uploadedAt', descending: true)
   ```

## Data Relationships

```
Firebase Auth User (UID)
    │
    └──> users/{userId} (User Profile Document)
            │
            ├──> attendance (Subcollection)
            │       ├── {attendanceId_1}
            │       ├── {attendanceId_2}
            │       ├── {attendanceId_3}
            │       └── ... (multiple attendance records)
            │
            └──> documents (Subcollection)
                    ├── {documentId_1}
                    ├── {documentId_2}
                    ├── {documentId_3}
                    └── ... (multiple uploaded documents)
```

### Relationship Details:

1. **Firebase Auth User → User Profile (1:1)**
   - Each Firebase Auth user has exactly one document in the `users` collection
   - Document ID matches the Firebase Auth UID
   - Path: `users/{userId}`

2. **User Profile → Attendance Records (1:Many)**
   - Each user document owns a subcollection of attendance records
   - Path: `users/{userId}/attendance/{attendanceId}`
   - No `userId` field needed - relationship is defined by path hierarchy
   - A user can have multiple check-ins per day
   - All attendance records are automatically scoped to the parent user

3. **User Profile → Documents (1:Many)**
   - Each user document owns a subcollection of uploaded documents
   - Path: `users/{userId}/documents/{documentId}`
   - No `userId` field needed - relationship is defined by path hierarchy
   - Actual file data stored in Firebase Storage
   - Metadata (filename, URL, size) stored in subcollection

### Benefits of Subcollection Architecture:
- ✅ **Data Isolation**: Each user's data is naturally isolated
- ✅ **Easy Deletion**: Deleting a user enables cascade deletion of all subcollections
- ✅ **Cleaner Queries**: No need to filter by `userId` - path defines scope
- ✅ **Better Security**: Security rules naturally scope to user context
- ✅ **Intuitive Structure**: Mirrors real-world ownership relationships

## Firebase Storage Structure

```
firebase_storage_root/
│
├── profile_images/
│   └── {userId}/
│       └── profile.jpg
│
└── documents/
    └── {userId}/
        ├── {documentId}_file1.pdf
        ├── {documentId}_file2.jpg
        └── {documentId}_file3.png
```

### Storage Bucket Details:

**Profile Images Path**: `profile_images/{userId}/profile.jpg`
- Overwritten each time user updates profile image
- URL stored in `users/{userId}.profileImageUrl`

**Documents Path**: `documents/{userId}/{documentId}_{originalFileName}`
- Each document gets a unique path
- URL stored in `documents/{documentId}.fileUrl`

## Indexes Required

With the subcollection architecture, indexing is simplified because queries are automatically scoped to the parent user document.

### Single Field Indexes:

1. **users/{userId}/attendance** subcollection:
   - `checkInTime` (Descending) - for fetching attendance history ordered by date
   - `checkInTime` (Ascending) - for date range queries

2. **users/{userId}/documents** subcollection:
   - `uploadedAt` (Descending) - for fetching documents ordered by upload date

### Why Composite Indexes Are NOT Needed:
- ✅ No `userId` filtering required - subcollection path provides user scope
- ✅ Single field indexes are sufficient for date-based queries
- ✅ Lower index maintenance overhead
- ✅ Reduced storage costs

*Note: Firebase may still prompt you to create indexes for complex queries. Follow the provided link in the error message to auto-create them.*

### Example 1: User Registration & Profile Setup
```
1. User authenticates with biometrics (or email/password)

3. App creates document in users/{UID}:

     phone: "",

   }
4. User completes profile setup
5. App updates users/{UID}:
   {
     name: "John Doe",
     phone: "+1234567890",
     designation: "Developer",
     profileImageUrl: "https://...",
     isProfileComplete: true
   }
```

### Example 2: Check-In Flow
```
1. User clicks "Check In" button
2. App fetches location (GPS + address)
3. App creates document in users/{userId}/attendance/{auto-generated-id}:
   {
     id: "att_123",
     checkInTime: Timestamp.now(),
     checkOutTime: null,
     checkInLocation: "123 Main St",
     checkInLatitude: 37.7749,
     checkInLongitude: -122.4194,
     checkOutLocation: null,
     checkOutLatitude: null,
     checkOutLongitude: null
   }
   
   Note: userId is implicit in the path, not stored in the document
```

### Example 3: Check-Out Flow
```
1. User clicks "Check Out" button
2. App fetches current location
3. App updates users/{userId}/attendance/{attendanceId}:
   {
     checkOutTime: Timestamp.now(),
     checkOutLocation: "123 Main St",
     checkOutLatitude: 37.7749,
     checkOutLongitude: -122.4194
   }
```

### Example 4: Weekly Stats Calculation
```
1. App queries attendance subcollection:
   Path: users/{userId}/attendance
   - Filter: checkInTime >= 7 days ago
   - OrderBy: checkInTime desc
   
   Note: No userId filter needed - query is already scoped to user

2. App groups results by unique dates

3. App calculates:
   - totalDays = number of unique dates
   - totalWorkingTime = sum of all workingHours for all sessions
   - averageHoursPerDay = totalWorkingTime / totalDays

4. App displays stats on dashboard
```

## Migration Guide: Flat Collections → Subcollections

If you currently have flat collections with `userId` fields, here's how to migrate:

### Current Structure (Flat Collections):
```
attendance (Collection)
  ├── att_001 → { userId: "abc123", checkInTime: ..., ... }
  ├── att_002 → { userId: "abc123", checkInTime: ..., ... }
  └── att_003 → { userId: "def456", checkInTime: ..., ... }
```

### Target Structure (Subcollections):
```
users/abc123/attendance
  ├── att_001 → { checkInTime: ..., ... }  // No userId field
  └── att_002 → { checkInTime: ..., ... }

users/def456/attendance
  └── att_003 → { checkInTime: ..., ... }
```

### Migration Steps:

1. **Create a backup** of your Firestore database
2. **Run migration script**:
   ```dart
   Future<void> migrateToSubcollections() async {
     final firestore = FirebaseFirestore.instance;
     
     // Migrate attendance
     final attendanceDocs = await firestore.collection('attendance').get();
     for (var doc in attendanceDocs.docs) {
       final data = doc.data();
       final userId = data['userId'];
       
       // Create in new location (subcollection)
       await firestore
         .collection('users')
         .doc(userId)
         .collection('attendance')
         .doc(doc.id)
         .set({
           ...data,
           'userId': FieldValue.delete(), // Remove userId field
         });
       
       // Delete old document
       await doc.reference.delete();
     }
     
     // Migrate documents (similar approach)
     final documentDocs = await firestore.collection('documents').get();
     for (var doc in documentDocs.docs) {
       final data = doc.data();
       final userId = data['userId'];
       
       await firestore
         .collection('users')
         .doc(userId)
         .collection('documents')
         .doc(doc.id)
         .set({
           ...data,
           'userId': FieldValue.delete(),
         });
       
       await doc.reference.delete();
     }
   }
   ```

3. **Update all queries** in your codebase to use subcollection paths
4. **Update security rules** to reflect subcollection structure
5. **Test thoroughly** before deploying to production

## Best Practices & Considerations

### Data Consistency
- Always use transactions when updating related fields
- Validate data on the client before writing to Firestore
- Use security rules to enforce data integrity

### Performance Optimization
- Use `.limit()` for paginated queries
- Index frequently queried fields
- Use `GetOptions(source: Source.server)` when fresh data is critical
- Cache data appropriately with `GetOptions(source: Source.cache)`

### Cost Optimization
- Minimize the number of document reads
- Use `ref.invalidate()` sparingly
- Batch operations when possible
- Delete old attendance records if not needed (archiving strategy)

### Security
- Always validate `userId` matches `request.auth.uid` in security rules
- Don't expose sensitive data in public documents
- Use Firebase Storage security rules for uploaded files

## Troubleshooting Common Issues

### Issue: "Missing Index" Error
**Solution**: Click the link in the error message to create the required composite index in Firebase Console.

### Issue: Stale Data After Check-In/Out
**Solution**: Use `GetOptions(source: Source.server)` and invalidate providers after writes.

### Issue: Multiple Check-Ins Counted as Separate Days
**Solution**: Group attendance by date (year-month-day) before counting unique days.

### Issue: Working Hours Not Calculating
**Solution**: Ensure both `checkInTime` and `checkOutTime` are set before calculating duration.

## Code Implementation Examples

### Firestore Service Methods (Updated for Subcollections)

```dart
class FirestoreService {
  final FirebaseFirestore _firestore = FirebaseFirestore.instance;
  
  // Reference to user's attendance subcollection
  CollectionReference _attendanceCollection(String userId) =>
    _firestore.collection('users').doc(userId).collection('attendance');
  
  // Reference to user's documents subcollection
  CollectionReference _documentsCollection(String userId) =>
    _firestore.collection('users').doc(userId).collection('documents');
  
  // Get today's attendance
  Future<AttendanceModel?> getTodayAttendance(String userId) async {
    final now = DateTime.now();
    final startOfDay = DateTime(now.year, now.month, now.day);
    final endOfDay = DateTime(now.year, now.month, now.day, 23, 59, 59);
    
    final query = await _attendanceCollection(userId)
      .where('checkInTime', isGreaterThanOrEqualTo: Timestamp.fromDate(startOfDay))
      .where('checkInTime', isLessThanOrEqualTo: Timestamp.fromDate(endOfDay))
      .orderBy('checkInTime', descending: true)
      .limit(1)
      .get(const GetOptions(source: Source.server));
    
    if (query.docs.isEmpty) return null;
    return AttendanceModel.fromMap(query.docs.first.data());
  }
  
  // Check in
  Future<void> checkIn(AttendanceModel attendance) async {
    await _attendanceCollection(attendance.userId)  // Removed userId from document
      .doc(attendance.id)
      .set({
        'id': attendance.id,
        'checkInTime': Timestamp.fromDate(attendance.checkInTime),
        'checkInLocation': attendance.checkInLocation,
        'checkInLatitude': attendance.checkInLatitude,
        'checkInLongitude': attendance.checkInLongitude,
        // No userId field needed!
      });
  }
  
  // Get attendance history
  Future<List<AttendanceModel>> getAttendanceHistory(String userId, {int limit = 20}) async {
    final query = await _attendanceCollection(userId)
      .orderBy('checkInTime', descending: true)
      .limit(limit)
      .get();
    
    return query.docs
      .map((doc) => AttendanceModel.fromMap(doc.data()))
      .toList();
  }
  
  // Get weekly stats
  Future<Map<String, dynamic>> getWeeklyStats(String userId) async {
    final now = DateTime.now();
    final sevenDaysAgo = now.subtract(const Duration(days: 7));
    
    final query = await _attendanceCollection(userId)
      .where('checkInTime', isGreaterThanOrEqualTo: Timestamp.fromDate(sevenDaysAgo))
      .orderBy('checkInTime', descending: true)
      .get();
    
    // ... calculation logic ...
  }
  
  // Upload document
  Future<void> uploadDocument(DocumentModel document) async {
    await _documentsCollection(document.userId)  // Removed userId from document
      .doc(document.id)
      .set({
        'id': document.id,
        'fileName': document.fileName,
        'fileUrl': document.fileUrl,
        'uploadedAt': Timestamp.fromDate(document.uploadedAt),
        'fileType': document.fileType,
        'fileSize': document.fileSize,
        // No userId field needed!
      });
  }
  
  // Get user documents
  Future<List<DocumentModel>> getUserDocuments(String userId) async {
    final query = await _documentsCollection(userId)
      .orderBy('uploadedAt', descending: true)
      .get();
    
    return query.docs
      .map((doc) => DocumentModel.fromMap(doc.data()))
      .toList();
  }
  
  // Delete document
  Future<void> deleteDocument(String userId, String documentId) async {
    await _documentsCollection(userId).doc(documentId).delete();
  }
}
```

### Updated Security Rules

```javascript
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    
    // User profile documents
    match /users/{userId} {
      // Users can read and write their own profile
      allow read, write: if request.auth != null && request.auth.uid == userId;
      
      // Attendance subcollection
      match /attendance/{attendanceId} {
        allow read: if request.auth != null && request.auth.uid == userId;
        allow create: if request.auth != null && request.auth.uid == userId;
        allow update: if request.auth != null && request.auth.uid == userId;
        allow delete: if request.auth != null && request.auth.uid == userId;
      }
      
      // Documents subcollection
      match /documents/{documentId} {
        allow read: if request.auth != null && request.auth.uid == userId;
        allow create: if request.auth != null && request.auth.uid == userId;
        allow delete: if request.auth != null && request.auth.uid == userId;
      }
    }
  }
}
```

### Key Changes Summary:

| Aspect | Flat Collections | Subcollections |
|--------|------------------|----------------|
| **Path** | `attendance/{id}` | `users/{userId}/attendance/{id}` |
| **userId Field** | ✅ Required | ❌ Not needed |
| **Query Scoping** | `.where('userId', isEqualTo: userId)` | Automatic (via path) |
| **Security Rules** | Check `resource.data.userId` | Check path `{userId}` |
| **Data Deletion** | Manual for each collection | Cascade with parent |
| **Indexes** | Composite (userId + field) | Single field only |
